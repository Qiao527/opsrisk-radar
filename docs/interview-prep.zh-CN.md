## 可能的追问

**为什么默认使用规则，而不是直接使用大模型？**
规则不需要 API 凭证，有明确的匹配证据，也方便离线演示；代价是会误报或
漏报。项目实现了可选混合评分，但目前没有真实 API 对比结果，不能声称
哪种方案更准确。

**数据源失败会怎样？**
每次抓取记录来源状态；低于配置的成功比例时运行失败。本地改动会在最近一次
已发布的运行部分成功时，在页面顶部提示覆盖可能不完整。静态页面无法立即
显示发布前失败的后续运行，数据年龄提示是现有的兜底方式。

**如何知道筛选结果有效？**
先依据书面规则盲审独立样本，再测量前 10 条中的有效比例和重要事件的召回，
同时查看误报、漏报与样本数量。当前没有人工标注结果，机器建议标签的分数
不能当作准确率。

**你和 AI 怎么分工？**
可以用案例中的来源覆盖提示说明实际流程：先提出检查方向，AI 检查并给出
可运行改动和测试；由人审查提示是否符合使用场景并决定是否接受。请只讲述
自己实际完成的审查和决定。

**这与真实 FDE 工作还差什么？**
目前是模拟客户场景。仍需要真实用户访谈、对客户流程和约束的理解、独立
效果评估，以及在合适环境中验证部署和交付。这个项目是练习这些能力的基础，
不是已经完成这些工作的证明。
